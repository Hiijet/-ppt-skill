# Interactive PPT Production

**逐页确认式 AI PPT 制作 Skill**

让 AI 按“先确认方案，再制作预览，修改后重新预览，满意后逐页定稿”的方式协作制作可编辑 PPT，而不是一次生成整套、最后集中返工。

适合学术汇报、论文分享、组会报告及其他需要沿用模板、核对原图、逐页审阅的演示文稿。

> 本项目是一套工作流指令、状态管理脚本和交互协议，不是一款独立的在线 PPT 编辑器。实际生成与预览需要 AI 所在环境提供相应工具。

## 核心功能

- **逐页确认**：每页先确认内容、图片、字体字号、颜色与布局，再开始制作。
- **真实预览**：查看当前页面实际渲染结果，不用占位图或旧截图代替。
- **修改后重新预览**：保留历史版本，局部修改后重新检查与审阅。
- **按钮直接定稿**：平台支持真实交互回传时，点击确认即有效，不要求聊天重复确认。
- **自动衔接下一页**：本页定稿成功后自动展示下一页方案，但不会跳过下一页的参数确认。
- **可编辑交付检查**：要求区分原生文字、表格、公式与图片，并检查实际导出的 PPTX。
- **跨平台移交**：通过明确的状态与交互约定复用流程，不把工具名称或私人文件路径写死在核心规则里。

## 工作方式

```text
提供模板与资料
    ↓
确认模板观察与拟继承样式
    ↓
确认当前页完整方案
    ↓
制作当前页并展示真实预览
    ↓
提出修改 → 归档旧版 → 修改并重新预览
    ↓
确认本页定稿
    ↓
自动展示下一页方案，等待确认
    ↓
按用户指定范围导出并检查 PPTX
```

**有两种不同的确认：**

| 操作 | 含义 |
|---|---|
| 按方案制作预览 | 允许制作当前页，不代表本页定稿 |
| 确认本页或本页定稿 | 批准当前预览版本，随后进入下一页方案 |

切换页签、放大预览或默认选中选项，都不算定稿。修改后的新版本必须重新预览与批准。

## 快速开始

### 1 准备材料

准备项目名称、PPT 模板以及论文或汇报文字；需要用图时提供原图与图注，图片也可稍后补充。本地执行环境还需指定保存目录，在线平台则按其文件上传和下载方式交付。

没有模板时请明确说明。学术组会规范是可选预设，不会因为题目属于学术研究而自动启用。

### 2 让 AI 读取 Skill

**支持 Skill 的平台**：下载仓库，将完整的 `interactive-ppt-production` 文件夹放入该平台规定的技能目录或按平台说明导入。具体安装方式以平台文档为准。

**不支持 Skill 导入但能读取文件的 AI**：提供完整项目文件，让它先读取 [SKILL.md](SKILL.md)，再按需读取参考文档。若无法读取压缩包，请解压后提供文件，不要只复制入口而遗漏引用内容。

**当前已安装本 Skill 的环境**：可以直接说“请使用 interactive-ppt-production，帮我逐页制作 PPT”。

### 3 复制启动指令

上传材料后，替换方括号中的内容：

```text
请使用 interactive-ppt-production，帮我逐页制作可编辑 PPT。

项目名称：[名称]
保存位置：[本地目录，或通过平台交付下载文件]
模板：[模板文件名]
内容来源：[论文或文字资料文件名]
用途与时长：[例如学术组会，15分钟]
封面信息：[汇报人、导师、日期；未知项留空]
学术组会预设：[不使用；或先解释规则，等我确认]

先读取 SKILL.md，检查你是否具备文件读取、PPTX 生成、真实预览
以及按钮事件回传能力；缺少能力请明确说明。

每页先展示文字、图片、字体字号、颜色和布局的完整方案。
我确认后只制作本页。修改后必须重新预览。
当前版本“确认本页”按钮即定稿，不再要求聊天重复确认。
定稿成功后自动展示下一页方案，等待我选择，不直接制作未来页。
无按钮回传能力时请说明，并改用真实表单或聊天确认。
最终按我指定的页码导出，不覆盖旧文件。
```

### 4 修改和导出

修改时，尽量说清“改哪里、改成什么、哪些不变”：

```text
右侧正文改为18 pt，小标题、图片和其他布局不变，请重新预览。
```

满意后点击当前版本的“确认本页”。如果没有可用按钮，在看到预览后回复：

```text
本页定稿，请展示下一页方案。
```

需要展示时，明确指定导出范围：

```text
请将第1—9页最新定稿版本导出为可编辑 PPTX。
只导出这些页面，另存新文件，不覆盖旧版。
请检查页数、文字可编辑性、原生表格及图片裁切，并提供文件。
```

## 环境要求与能力边界

| 使用方式 | 需要的能力 | 能完成什么 |
|---|---|---|
| 纯文字协作 | 阅读指令并进行对话 | 收集要求、规划内容和提出审阅意见 |
| 实际制作与交付 | 文件操作、可编辑 PPTX 制作工具、页面渲染工具 | 制作、预览、修改和导出文件 |
| 可视化按钮协作 | 在上项基础上具备真实用户事件回传能力 | 在界面中批准方案、提交修改和定稿 |

- 本包**不自带 PPTX 编译器、论文素材或商业模板**。
- 本包**不自带可直接运行的完整网页工作台或按钮服务**；提供的是适配协议，界面需由宿主平台或单独适配器实现。
- 静态 HTML 的按钮变色或浏览器本地存储，不等于后端已记录批准。
- 不保证所有 AI 平台具有相同界面，也不承诺不同模型自由排版得到逐像素相同结果。
- 论文原图内部的标签通常仍是图片，不应被称为可编辑文字。原生表格或数学对象须由实际后端支持并验证。
- 学术预设与公式工具不是隐式附带能力；无法使用时必须说明，不能把线性文字或图片称为 MathType 对象。

## 两种执行后端

### 已有 PPT Master

遵守环境中实际安装的 PPT Master 入口、完整性检查及逐页工作流程，以 `page_workflow.json` 为唯一项目状态。不要再用本包的独立状态器重复记录同一项目，也不要绕过原后端的质量与确认关卡。

### 没有 PPT Master

可使用 `scripts/workflow.py` 管理参数确认、预览、修改归档和批准记录，再配合实际可用的 PPTX 制作及渲染工具。

这个脚本**只管理流程和证据，不制作幻灯片、不编译 PPTX，也不会自动替用户批准**。命令和数据要求见 [独立状态器说明](references/state-and-schema.md)。

## 项目文件如何保存

```text
主文件夹/
├── sources/                 # 共享模板及模板学习记录
└── 项目名称/
    ├── product/             # 页面源、素材、制作记录、预览及历史版本
    └── output/              # 最终交付文件
```

不擅自移动原始资料或覆盖旧交付。继续已有项目时，先恢复制作记录，不重复初始化。换 AI 或换电脑时，应移交项目状态、素材、页面源和版本证据，而不是只提供截图或最终 PPTX。

## 脚本与测试

普通使用者可以让具备工具能力的 AI 执行，不必手动运行命令。

- 独立状态器及其测试使用 Python 标准库。
- `render_preview.mjs` 需要环境已有 Node.js、Playwright 和可用浏览器；本包不会自动安装这些依赖。
- 实际 PPTX 制作、PDF 解析及 Office 渲染工具按宿主环境另行配置。

开发者可在有写入权限的临时目录运行：

```bash
python scripts/test_workflow.py --tmp-root /path/to/approved-temp-dir
```

测试使用模拟材料验证审批前置条件、单页等待、输入变化失效、修改归档及导出就绪等流程，不等于真实 PPTX 排版测试。可视化协议中的验收场景也不代表已在所有平台实现或通过 UI 自动测试。

## 常见问题

**能一次自动生成整套 PPT 吗？**  
本 Skill 的重点是逐页协作。每页确认后才制作，本页定稿后只自动进入下一页方案，不代替用户批准后续页面。

**为什么 AI 只能给文字方案？**  
它可能没有 PPTX 制作或渲染工具。提示词和 Skill 不能凭空增加运行环境的工具能力。

**界面预览正确，导出的图片却不对怎么办？**  
需要检查真实 PPTX，尤其是拼图裁切、色标及大背景水印。源页面预览不能代替导出文件检查。

**更换模型能得到同样结果吗？**  
可以共享流程、参数和审批记录。严格复现版式还需复用已批准页面源、原始素材、字体及固定的导出和渲染环境。

## 素材与许可

使用者应自行确认模板、字体、论文原图及其他素材的使用和公开传播权限。不要把私人项目、未公开研究数据或无权公开的模板上传到公共仓库。

第三方工具和依赖遵循其各自许可。本项目的具体授权以仓库实际提供的 `LICENSE` 为准；没有许可证时，不应把仓库公开等同于授予开源使用许可。
